# 語彙アプリ同期：安全な本番移行と復旧手順

> **状態：手順書のみ。2026-10-12時点で、Apps Scriptの改修版は本番未反映。**
> この文書が存在しても、データの完全バックアップ・復元テストを実施したことにはならない。

## 1. 対象と独立した保護範囲

| 対象 | 用途 | 変更・保全時の注意 |
| --- | --- | --- |
| Google Sheets 正本 | 単語・分類情報・単語ID・変更履歴・監査用データ | シート全体を保護。IDや語彙を一部だけ復元すると参照整合性が崩れる |
| Firestore `privateWords/vol1` ～ `vol4` | アプリが表示する同期済み単語CSV | 書換え前に**4文書すべての全フィールド**を退避。gzip格納項目と `syncedAt` を含む |
| Firestore `privateUsers/{uid}` | お気に入り・苦手・学習履歴等、ユーザー別状態 | 単語データの復旧に巻き込んで上書きしない。必要なら独立して退避 |
| Firestore `portfolioUsers/{uid}` | 別用途の個人状態 | この語彙同期では触らない |
| Apps Script プロジェクトの現在のエディタ版 | `syncAllVolumesToFirestore()` 等の手動実行 | Web Appのデプロイバージョンとは別。編集前に既存版を保全 |
| Firebase Firestore Rules | 実データのアクセス制御 | 本番の2 UID許可リスト等を維持。GitHubの旧 `firestore.rules` をデプロイしない |
| Firebase Hosting | ブラウザ側の配信 | `main`へのマージはHosting本番デプロイを起動し得る。Apps Scriptの更新ではない |

## 2. 確認済みのバックアップと未確認箇所（2026-10-12）

- 元のGoogle Sheets正本は6シート。2026-08-16/17の旧バックアップはどちらも1シートのみ。
- **6シートを複製した非公開Google Sheetsバックアップを2026-10-12に新規作成済み**。所有者のみの権限、シート構成、主要列の見出し、変更履歴冒頭の一部が正本と一致することを確認。
- 非公開コピーのファイル名：`vocab-app-study_FULL_BACKUP_2026-10-12_pre-rollout`。**個人用Driveリンク・ファイルIDは公開リポジトリに記載しない。**
- 未実証：バックアップと元データの**全セル比較**、当該コピーからの復元試験、**Firestore実データのバックアップ**、Firestoreからの復旧試験。
- このSheetsバックアップだけではFirestoreの現在の4巻・学習記録を復旧できない。**Firestore退避未完了のまま同期本番変更を開始しない。**

## 3. 本番変更の前提条件（全部満たすまで停止）

- [ ] 作業を行う日付と開始直前の正本の状態を確認する。前回コピー後にデータが更新されていたら**新しい非公開バックアップを追加**する（正本は変更しない）。
- [ ] Google Sheetsのコピーが6シート揃うことを確認し、`シート1` のID・分類・語彙データと履歴を抜粋照合。現在のバックアップは冒頭サンプルまで確認済み。
- [ ] 権限を持つ環境から、`privateWords/vol1` ～ `vol4` の**元の文書フィールド全体**を読み取り専用で退避する。退避データは非公開にして、件数・文書ID・`syncedAt`・復元方法を記録する。
- [ ] 学習状態の保全が必要なら、別途`privateUsers`も適切な権限・安全な場所でバックアップする。個人UID・認証情報をGitHubに掲載しない。
- [ ] Firestoreの退避方法は、Google Cloudの管理エクスポート（必要な課金設定、Cloud Storage、権限を確認してから利用）か、レビュー済みの読み取り専用エクスポートを採用。**費用が発生する操作を無断実施しない。**
- [ ] 復旧用に退避データを読み出せることを確認する。可能なら本番とは別の検証環境に復元し、復元手順をテストする。
- [ ] 現在のApps Scriptエディタの `Code.gs` を安全な別バージョン／非公開の控えとして保全し、切戻し対象を明確にする。歴史上のデプロイv4と編集画面の現在のソースは必ずしも一致しない。
- [ ] 本番Firestore Rulesが許可された2 UIDに制限されていることを確認し、不要なルール公開操作をしない。
- [ ] 本番FirestoreとSheetsの同期時にデータ更新を並行実行しない。旧 `SYNC_TOKEN` は復活させず、公開Web App経由同期は再有効化しない。

## 3a. 無料枠内での4巻退避を試みる場合（補助スクリプト・未実行）

- `apps-script/FirestoreBackupStandalone.gs` は**同期コードを置き換えずに**既存のApps Scriptプロジェクトへ独立した `.gs` ファイルとして追加できるようにした補助関数。既存の `CONFIG` と `getAccessToken()` を利用し、Firestore RESTの `GET` で `privateWords/vol1`～`vol4` を取得する。Firestoreへの書込み処理は含まない。
- 4文書すべての読取・名前・CSVフィールド検査が成功した場合のみ、**個人のGoogle Drive**にJSONバックアップを1ファイル作成し、作成直後に共有が非公開であることを検証する。非公開でなければ新規ファイルをゴミ箱に移して失敗扱いにする。保存するのはFireStore RESTの文書本体（フィールド・メタデータ）で、プライベートな認証トークンや秘密鍵は保存しない。
- 旧 `Code.gs` 全体を置き換えたり、Web Appを再デプロイしたり、`dryRun()`を実行する必要はない。ユーザーの承認なしにこのスクリプトを実行しない。
- モックによる読取専用・全巻成功時のみファイル作成のテストは可能だが、Apps Script実機のDrive許可・Firestore権限・実データの量、ファイル作成時の容量制限や復元可能性は**未検証**。無料であることも保証しない（容量枠・Apps Script実行枠内であれば追加のクラウドエクスポート課金を避けられる設計）。
- この補助関数の実行結果として作成されたJSONファイルは、**読めることと4文書が揃っていること、共有が「制限付き」であること**を確認して初めてFirestore4巻のバックアップとして記録する。**学習状態 `privateUsers` はバックアップ対象外**。
- 実際の復元は別途設計・承認・テストが必要。JSON取得のみで切戻し作業が検証されたとは言わない。

## 4. 手動移行の順序（現時点では**実行しない**）

1. GitHubドラフトPRの最終差分、テスト、Hostingプレビューを確認し、問題なければ移行日を決める。**PRのマージとApps Scriptコードの更新を同一作業として扱わない。**
2. Apps Scriptの**編集画面の現在のソース**を保存した後、改修版 `apps-script/Code.gs` を反映する。スプレッドシート正本ではなく、一時的な検証用コピーで最初に挙動を確認する。検証用コピーの編集でバックアップ本体を壊さない。
3. `CONFIG.firebaseProjectId`、`CONFIG.mode`、`CONFIG.sourceSheetName`、4巻の設定を照合。`CLIENT_EMAIL` と `PRIVATE_KEY` はScript Propertiesの既存値を安全に利用し、画面共有・GitHub公開をしない。
4. **改修版の** `dryRun()` で巻ごとの単語数、分類、CSVサイズ、必要に応じた圧縮を検査。元のv4 `dryRun()` はシートIDを書き込むため、**旧版では絶対に実行しない**。改修版の `dryRun` が書き込みを行わないことはモックテスト済みだが、実行環境で未確認。
5. 事前バックアップと検証を終えた時点で、改修版の `syncAllVolumesToFirestore()` を**1回だけ**手動実行し、正常応答・4巻分の保存結果を確認。タイムアウトや曖昧な応答時は無条件に連続再試行しない。
6. Firestoreで`privateWords/vol1`～`vol4`の`syncedAt`、エンコード種別、単語件数を確認。ブラウザの「単語更新」後に全巻の読み込みと学習状態の保持を確認。
7. Firestore Rulesを**変更しない**。Web Appを「全員」に戻さない。旧共有トークンを再設定しない。
8. Hosting本番が必要な別変更はアプリUI検証後に分けて実施する。GitHub PRマージでHosting本番ワークフローが動くので、反映タイミング・ロールバックを別途管理する。

## 5. 障害発生時の切戻し

- **同期前にエラー／検証失敗：** 同期を中止し、原則データを操作しない。生成IDがSheetsに一部残った場合、既存IDの再利用が可能か内容を先に調べ、無差別に全シートを上書きしない。
- **Firestore Commitがエラー：** 同一コミットの4巻単位原子性はFirestore側で保証されるが、応答欠落・タイムアウト時には確定した可能性がある。元の4文書の `syncedAt` と内容を読み取り、書込状態を確認してから対処。
- **改修版に不具合：** Apps Script編集画面に保存した以前のコードへ戻す。Web Appデプロイv4の復元と、エディタ側のコード切戻しは別作業であることに注意。
- **Firestoreデータが不正：** 事前に安全に退避した4文書の完全なフィールドを、権限を持つ環境で復旧し、元のデータと時刻を照合。**バックアップ取得前に復元可能と断定しない。** Firestore Security Rulesは変更しない。
- **Google Sheetsの正本が不正：** 6シートの非公開バックアップから、他の更新との差分・学習記録との整合性を確認して復旧。古いバックアップで現在の正本全体を無条件に置換しない。
- **学習状態だけに障害：** `privateUsers`を別案件として扱い、単語4巻の復旧と分離する。変更しなかったユーザー状態はむやみに巻き戻さない。

## 6. 完了判定

下記の証拠が揃うまでは「本番移行完了」と言わない。

- [ ] Firestore4巻の**読み取り可能な**直前バックアップと、必要に応じたユーザー状態の保全
- [ ] Apps Script編集画面の変更前ソース控え／切戻し先
- [ ] 改修版の実環境での無書込 `dryRun()` 実証
- [ ] Firestore4巻の実データ・同期結果・ブラウザの表示を照合
- [ ] 公開ルールを意図せず緩めていないことの確認
- [ ] 障害時の切戻し経路が明確であること

**禁止：** 本番Firestore Rulesの一括上書き、旧トークン復活、Web Appの無差別公開、未バックアップの同期、費用が発生するエクスポートの無断開始。
